Terraform Essentials

This page explains how our Terraform pipeline chooses Terraform provider versions (such as AWS 6.66.0), and what to change to get AWS provider 6.68 or newer. Terraform runs inside a Docker image stored in Amazon ECR in the prod state account. That image already contains the provider ZIPs, so the pipeline can only use providers that are in the image.

3Pipeline flow: how a provider version gets chosen

CodeBuild → Docker image → apply.sh → terraform init → .terraform.lock.hcl selects 6.66.0 → the image already has 6.66.0 → Terraform uses it.

  1. CodeBuild starts the Terraform Docker image terraform-docker-repo:beta.
  2. The image already contains several provider ZIPs: AWS 5.100.0, AWS 6.66.0 and AWSCC 1.103.0.
  3. CodeBuild downloads the repository into /codebuild/output/…/src.
  4. It reads apply.yml and runs . aide_scripts/apply.sh.
  5. apply.sh runs terraform init.
  6. terraform init reads the Terraform code (required_providers) and .terraform.lock.hcl.
  7. The lock file tells Terraform to use AWS provider 6.66.0.
  8. Terraform looks in the image and finds terraform-provider-aws_6.66.0_linux_amd64.zip.
  9. That is why the log says Using previously-installed hashicorp/aws v6.66.0.

4Reading the terraform init log

# CodeBuild log, terraform init
Initializing provider plugins...
- Reusing previous version of hashicorp/aws from the dependency lock file
- Using previously-installed hashicorp/aws v6.66.0

Terraform has been successfully initialized!

What it means

The lock file pinned 6.66.0, and that exact version was already in the image, so Terraform downloaded nothing. The version comes from the lock file plus what's in the image. It is not simply the newest version available.

Why 6.68+ won't appear by itself

Even if you change the constraint to >= 6.68.0, terraform init can only pick from the ZIPs in the image. Until 6.68+ is added to the image, init fails with "no available releases match the given constraints".

5How to get AWS provider 6.68+

The main blocker is the image: it does not contain AWS 6.68+ yet. Add the provider to the image first, then update the code and lock file.

Check the portal

Open the Terraform software portal to see if 6.68+ is already published for the pipeline. If it is, only the image tag may need changing. If not, request or add it.

Add the provider ZIP to the Docker image

Download the Linux build from HashiCorp, check its SHA-256, and copy it to the same folder where the image keeps the other provider ZIPs.

Download and verify (example: 6.68.0)
V=6.68.0
curl -fsSLO https://releases.hashicorp.com/terraform-provider-aws/${V}/terraform-provider-aws_${V}_linux_amd64.zip
curl -fsSLO https://releases.hashicorp.com/terraform-provider-aws/${V}/terraform-provider-aws_${V}_SHA256SUMS
grep linux_amd64 terraform-provider-aws_${V}_SHA256SUMS | sha256sum -c -
Dockerfile: add next to the existing provider ZIPs
# Use the same directory the image already uses for the 5.100.0 / 6.66.0 / awscc ZIPs
COPY terraform-provider-aws_6.68.0_linux_amd64.zip <existing-provider-dir>/

Build and push the image to ECR (prod state account)

ACCOUNT=<prod-state-account-id>
REGION=<region>
REPO=$ACCOUNT.dkr.ecr.$REGION.amazonaws.com/terraform-docker-repo

aws ecr get-login-password --region $REGION | docker login --username AWS --password-stdin $ACCOUNT.dkr.ecr.$REGION.amazonaws.com
docker build -t $REPO:beta .
docker push $REPO:beta

CodeBuild pulls :beta, so pushing to the same tag updates the pipeline. If you prefer a new tag, also update the CodeBuild project's image.

Update the Terraform code and lock file

versions.tf
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = ">= 6.68.0, < 7.0.0"
    }
  }
}
Refresh the lock file with Linux hashes (the pipeline runs on linux_amd64)
terraform init -upgrade
terraform providers lock -platform=linux_amd64 -platform=windows_amd64
git add .terraform.lock.hcl versions.tf
git commit -m "Upgrade AWS provider to 6.68"

Run the pipeline and confirm

The terraform init log should now show Using previously-installed hashicorp/aws v6.68.x. Run a plan first and check for changes caused by the new provider before you apply.

6Troubleshooting

Symptom in CodeBuild logCauseFix
Using previously-installed hashicorp/aws v6.66.0 (wanted newer)The lock file still pins 6.66.0.Run terraform init -upgrade, then terraform providers lock, and commit .terraform.lock.hcl.
no available releases match the given constraintsThe constraint asks for a version that isn't in the image.Add the provider ZIP to the image (step 5.2) or relax the constraint.
doesn't match any of the checksums previously recorded in the dependency lock fileThe lock file only has hashes for your laptop's platform.terraform providers lock -platform=linux_amd64 and commit.
New image pushed but pipeline still uses old providersCodeBuild uses a different tag or a cached image.Check the CodeBuild project's image URI and tag. Make sure you pushed to :beta in the prod state account.
